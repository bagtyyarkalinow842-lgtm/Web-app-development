# 📖 «Живая книга» — Рецензирование и комментарии к дипломным работам в реальном времени

> Веб-платформа для совместного анализа и рецензирования черновиков академических работ (ВКР, курсовых проектов, научных статей). Сервис позволяет студентам получать обратную связь по научному стилю и содержанию от сокурсников (включая анонимный режим), а преподавателям — утверждать исправления специальной «зеленой меткой».

## 📌 Функциональные требования к проекту

### 1. Модуль публикации и работы с документами

* [ ] Загрузка черновиков работ в форматах `.docx`, `.md` или вставка структурированного текста.
* [ ] Полноэкранный режим чтения и анализа текста с разбивкой на структурные разделы (Введение, Главы, Заключение, Список литературы).
* [ ] Настройки приватности работы: публичный доступ, доступ по ссылке, доступ только своей учебной группе или преподавателю.

### 2. Подсистема интерактивного комментирования (Core Feature)

* [ ] **Inline-комментирование:** выделение произвольного фрагмента/фразы текста курсором и открытие карточки замечания на боковой панели.
* [ ] **Категоризация заметок:** выбор типа ошибки при создании замечания (например: *«Научный стиль»*, *«Нарушение ГОСТ»*, *«Фактическая ошибка / Логика»*, *«Опечатка / Пунктуация»*).
* [ ] **Режим анонимности:** переключатель «Оставить комментарий анонимно» или под своим никнеймом для снятия барьера критики между студентами.
* [ ] **Ветки обсуждения (Threads):** возможность автора диплома ответить на замечание и прикрепить вариант исправления.

### 3. Модуль преподавателя («Зеленая метка»)

* [ ] Ролевая модель доступа: `Студент-автор`, `Рецензент (сокурсник)`, `Научный руководитель (Преподаватель)`.
* [ ] Механизм **«Зеленой метки»**: подтверждение преподавателем того, что замечание студента было обоснованным, а автор работы корректно внес исправление (статус *Resolved / Принято*).
* [ ] Прогресс-бар готовности диплома (процент устраненных замечаний от общего числа правок).

### 4. Синхронизация и Realtime

* [ ] Мгновенное отображение новых комментариев и реакций без перезагрузки страницы (через WebSockets / SSE).
* [ ] Индикация активных читателей текущей главы.

## Ресурс №1: Overleaf (Академическое рецензирование)

* **URL:** `https://www.overleaf.com`
* **Назначение:** Совместное написание и проверка научных статей, поддержка inline-комментариев и резолва правок научным руководителем.

### 1. Архитектура и стек технологий
* **Тип архитектуры:** Комплексный SPA / SSR с постоянным дуплексным соединением.
* **Frontend:** React, Angular (исторические модули интерфейса), CodeMirror / Monaco Editor для рендеринга и подсветки исходного кода LaTeX, PDF.js для просмотра скомпилированного документа.
* **Backend и API:** Node.js, Ruby on Rails, связка с сервисами компиляции TeXLive.
* **Сетевой обмен:** Использование WebSocket (Socket.IO) для передачи дельт правок в реальном времени (Operational Transformation / CRDT), REST API для управления проектами и файлами.
* **Веб-сервер:** Nginx, Cloudflare CDN.

### 2. Семантические элементы HTML5
* `<header>` — 1 шт. (верхняя панель управления проектом, компиляцией и доступом).
* `<nav>` — 2 шт. (файловое дерево проекта слева и переключатели режимов «Source / Rich Text»).
* `<main>` — 1 шт. (рабочая область: редактор кода + окно предпросмотра PDF).
* `<aside>` — 1 шт. (боковая панель замечаний и истории изменений «Review / Track Changes»).
* `<footer>` — 1 шт. (статусная строка: количество слов, статус синхронизации).

### 3. Семантические классы и структура стилей
* Используется компонентный подход на базе CSS Modules и BEM-подобных соглашений:
  * `.ide-container` — обертка рабочей области редактора.
  * `.editor-pane`, `.pdf-viewer-pane` — панели исходного кода и результата.
  * `.review-panel__comment-card` — карточка инлайн-замечания.
  * `.review-panel__comment-status--resolved` — состояние решенной правки.

### 4. Адаптивность и media-запросы
* Ресурс ориентирован преимущественно на десктопные рабочие места исследователей.
* Ключевые точки адаптации (`breakpoints`):
  * `@media (max-width: 768px)` — автоматическое скрытие панели предпросмотра PDF, сворачивание бокового файлового дерева в выдвижное гамбургер-меню.
  * `@media (max-width: 1024px)` — переход боковой панели комментариев в плавающий оверлей.

### 5. Анализ с помощью Lighthouse
* **Условия проверки:** Домашняя сеть Wi-Fi (скорость ~90 Мбит/с), Google Chrome v128, режим Desktop, тестирование страницы открытого редактора проекта.
* **Performance:** 71 / 100 (снижено из-за тяжелых бандлов редактора CodeMirror и движка PDF.js).
* **Accessibility:** 88 / 100.
* **Best Practices:** 95 / 100.
* **SEO:** 82 / 100 (для закрытой зоны редактора закрыт через `robots.txt`).

### 6. Хранилище (Storage) и Cookies
* **Local Storage / Session Storage:**
  * Сохранение клиентских настроек отображения редактора: `editor-theme`, `pdf-zoom-level`, `split-ratio` (пропорция разделения экрана).
* **Cookies:**
  * Сессионный идентификатор пользователя (`_overleaf_session`), CSRF-токен защиты (`csrf-token`), куки маршрутизации нагрузки Cloudflare (`__cf_bm`).

### 7. Маркетинг и веб-аналитика (Network Filter)
* `google-analytics.com` / `gtag.js` — общий сбор статистики взаимодействия.
* `tagmanager.google.com` — Google Tag Manager для управления событиями.
* Внутренняя телеметрия сервиса через эндпоинты `/metrics` и `/analytics`.

## Ресурс №2: Hypothesis (Веб-аннотации и рецензирование)

* **URL:** `https://web.hypothes.is`
* **Назначение:** Открытый сервис комментирования и аннотирования веб-страниц, документов и PDF в образовательной и научной сфере.

### 1. Архитектура и стек технологий
* **Тип архитектуры:** Встраиваемый клиент (iframe/overlay) + веб-приложение на Python (Pyramid framework).
* **Frontend:** Preact / React, TypeScript, кастомный движок текстового позиционирования (W3C Web Annotation Data Model).
* **Backend и API:** Python, PostgreSQL, Elasticsearch для полнотекстового поиска по аннотациям.
* **Сетевой обмен:** WebSocket для трансляции появления новых заметок участникам группы в реальном времени, JSON-LD REST API.

### 2. Семантические элементы HTML5
* `<aside>` — 1 шт. (основной контейнер выезжающей боковой панели аннотаций).
* `<article>` — 12 шт. (каждый отдельный комментарий и аннотация оформлен семантической статьей).
* `<header>` — 12 шт. (мета-шапка комментария: имя рецензента, роль, временная метка).
* `<nav>` — 1 шт. (панель сортировки заметок: по дате, по автору, по положению в тексте).

### 3. Семантические классы и структура стилей
* CSS-классы построены по модульному принципу:
  * `.annotator-frame` — контейнер iframe-виджета.
  * `.annotation-card__body` — текст замечания.
  * `.annotation-card__tags` — теги замечания (например, «стиль», «ГОСТ»).
  * `.annotation--highlighted` — класс текстового диапазона в DOM, привязанного к заметке.

### 4. Адаптивность и media-запросы
* Панель адаптируется под ширину родительского окна:
  * `@media (max-width: 480px)` — панель комментариев разворачивается на 100% ширины экрана смартфона, закрывая сам текст.
  * `@media (min-width: 768px)` — панель занимает фиксированные 420px справа от анализируемого текста.

### 5. Анализ с помощью Lighthouse
* **Условия проверки:** Домашняя сеть Wi-Fi (скорость ~90 Мбит/с), Google Chrome v128, режим Desktop, проверка клиентского расширения на веб-странице с текстом.
* **Performance:** 89 / 100.
* **Accessibility:** 94 / 100 (высокий уровень контрастности и фокус-менеджмента для скринридеров).
* **Best Practices:** 100 / 100.
* **SEO:** 90 / 100.

### 6. Хранилище (Storage) и Cookies
* **Local Storage:** Сохранение состояния свернутости/развернутости боковой шторки, кэш черновика неопубликованного комментария.
* **Cookies:** Идентификатор авторизованного пользователя, токен группы доступа к документу.

### 7. Маркетинг и веб-аналитика (Network Filter)
* Посторонние коммерческие трекеры минимизированы.
* Фиксируются внутренние события взаимодействия через эндпоинты `/api/telemetry`.

## Ресурс №4: Google Docs (Inline-редактирование и комментарии)

* **URL:** `https://docs.google.com`
* **Назначение:** Эталонный облачный текстовый редактор с системой инлайн-комментирования, резолва замечаний и предложений правок в режиме реального времени.

### 1. Архитектура и стек технологий
* **Тип архитектуры:** Высоконагруженный SPA со сложным собственным Canvas/DOM-рендерингом.
* **Frontend:** Собственный рендерер на Closure Tools, Canvas-отрисовка глифов и курсоров, Web Workers для фонового синтаксического анализа и проверки правописания.
* **Backend:** Собственная инфраструктура Google (C++, Java, Spanner).
* **Сетевой обмен:** Полнодуплексный WebChannel / WebSocket, кастомный протокол передачи дельт Operational Transformation.

### 2. Семантические элементы HTML5
* Из-за глубокой виртуализации интерфейса семантические HTML5-теги в чистом виде почти не используются.
* Вся семантика реализована через **WAI-ARIA** атрибуты поверх `<div>`:
  * `role="application"` — указание доступности на интерактивное веб-приложение.
  * `role="document"` — рабочая область текста документа.
  * `role="complementary"` — лента боковых комментариев и задач.
  * `aria-live="polite"` — объявление о появлении новых замечаний для пользователей скринридеров.

### 3. Семантические классы и структура стилей
* Классы сильно обфусцированы сборщиком в целях минимизации размера страницы (например: `.kix-appview`, `.docos-anchoredreplyview`, `.apps-share-sprite`).
* Назначение элементов определяется специализированными дата-атрибутами: `data-target="comment"`, `data-resolved="false"`.

### 4. Адаптивность и media-запросы
* На десктопе окно комментариев позиционируется абсолютно рядом с выделенным абзацем.
* При уменьшении ширины экрана (`@media (max-width: 900px)`):
  * Комментарии схлопываются в круглые пиктограммы-бейджи на правом поле страницы.
  * При клике на бейдж разворачивается модальное окно с тредом замечания.

### 5. Анализ с помощью Lighthouse
* **Условия проверки:** Домашняя сеть Wi-Fi (скорость ~90 Мбит/с), Google Chrome v128, режим Desktop, открытый документ со списком замечаний.
* **Performance:** 76 / 100.
* **Accessibility:** 96 / 100 (колоссальная поддержка экранных дикторов и навигации клавишами).
* **Best Practices:** 100 / 100.
* **SEO:** Не применимо (приватная рабочая область).

### 6. Хранилище (Storage) и Cookies
* **IndexedDB:** Огромная локальная база данных для поддержки полноценного Offline-режима (редактирование без интернета с последующей синхронизацией).
* **Local Storage / Session Storage:** Временные метки авторизации, кэш пользовательских шкал инструментов.
* **Cookies:** `SID`, `HSID`, `SSID` — единая система аутентификации аккаунтов Google Accounts.

### 7. Маркетинг и веб-аналитика (Network Filter)
* Отсутствуют внешние счетчики и пиксели сторонних рекламных систем.
* Используются закрытые внутренние сервисы сбора ошибок (`/client-telemetry`, `play.google.com/log`).

| 3 | **Анонимный режим рецензирования для студентов** | Студенческие сообщества, Hypothesis | **Must have** (P0) | Снимает психологический барьер: сокурсники могут свободно указывать на ошибки черновика инкогнито или под никнеймом. |
| 4 | **Ролевая модель (Студент-автор / Рецензент / Преподаватель)** | Overleaf, Google Docs | **Must have** (P0) | Разграничение прав: только преподаватель может подтверждать закрытие ошибки зеленой меткой. |
| 5 | **Обновление замечаний в реальном времени (WebSockets)** | Google Docs, Overleaf | **Should have** (P1) | Студент и рецензенты видят новые комментарии и статусы правок моментально без ручной перезагрузки страницы (`F5`). |
| 6 | **Категоризация замечаний (ГОСТ, Научный стиль, Логика)** | Академические чеклисты | **Should have** (P1) | Позволяет фильтровать список правок (например, исправить сначала все сноски по ГОСТу, затем логические неточности). |
| 7 | **Вложенные ветки обсуждения замечания (Threads)** | Hypothesis, Google Docs | **Should have** (P1) | Возможность вести аргументированную научную дискуссию вокруг конкретного замечания к абзацу. |
| 8 | **История изменений и сравнение версий черновика (Diff)** | Overleaf, Git | **Could have** (P2) | Наглядная демонстрация того, как изменился абзац после замечания перед одобрением преподавателем. |
| 9 | **Экспорт итогового отчета о рецензировании в PDF** | Overleaf | **Could have** (P2) | Возможность приложить протокол рецензирования черновика к пакету документов на защиту кафедры. |
| 10 | **Автоматический AI-линтинг оформления по ГОСТ** | Лингвистические анализаторы | **Won't have** (P3) | Полезная опция, отложенная на следующие версии из-за сложности реализации в рамках лабораторной работы. |
